업무 바로가기

일일 운영 루틴 순서 — 미확정 복구 → 보상 재처리 → 대사 확인 → 정산 실행·지급.

미확정(UNKNOWN) 결제 복구

웹훅 누락·타임아웃으로 방치된 결제를 PG 조회로 확정합니다. UNKNOWN은 "모름"을 상태로 보존한 것 — 추측으로 성공/실패 처리하지 않습니다.

보상 태스크 (망취소)

승인 후 재고 부족 등으로 발생한 자동 망취소 태스크. 재시도 소진(FAILED) 건은 여기서 재처리합니다.

정산 대사

내부 원장 vs PG 정산 파일 대조 결과 중 사람 확인이 필요한(PENDING) 불일치 목록. 대사는 정합성의 최종 방어선입니다.

정산 · 지급

구매확정(CONFIRMED) 항목을 일 단위 집계 — 수수료 2.7% + 수수료 VAT 10% → 지급액과 지급예정일(정산일+2영업일) 산출. 집계된 정산(CREATED)을 지급 확정(PAID_OUT)합니다.

분쟁 · 차지백

차지백 웹훅(HMAC 서명) 수신 → 분쟁 개시(chargebackId 멱등) → 증빙 제출 → 승/패 확정. 패소(LOST) 시 원장 역분개로 사후 정합을 맞춥니다.

차지백 웹훅 시뮬레이션

로컬 웹훅 시크릿으로 서명을 계산해 실제 웹훅 엔드포인트로 전송합니다.

분쟁 처리

강제취소 · 2인 승인 (maker-checker)

요청자와 승인자가 반드시 달라야 실행됩니다. 요청자 본인이 승인하면 MAKER_CHECKER_VIOLATION으로 차단.

FDS 사후 탐지 심사 큐

결제 완료 이벤트를 비동기 평가해 REVIEW/BLOCK을 큐에 적재합니다. 거부 시 카드 블랙리스트에 등록됩니다.

DLQ (실패 이벤트)

멱등 컨슈머가 실패를 흡수해 격리한 데드레터. 실패가 이벤트 흐름을 막지 않게 하고, 격리 건은 여기서 재처리합니다.
