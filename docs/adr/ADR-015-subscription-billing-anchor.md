# ADR-015. 다음 청구일을 직전 청구일이 아니라 앵커에서 계산한다

- 상태: 채택
- 관련: `subscription` 모듈, `V29__subscription_anchor_day.sql`, `BillingCycle`

## 문제

다음 청구일을 이렇게 계산하고 있었다.

```java
LocalDate nextBillingDate = subscription.getNextBillingDate().plusMonths(1);
```

`LocalDate.plusMonths`는 그 달에 없는 날짜를 말일로 당긴다. 1월 31일에 한 달을 더하면 2월 28일이고,
여기까지는 맞다. 문제는 **그 결과를 다시 기준으로 삼는 것**이다. 2월 28일에 한 달을 더하면 3월 28일이
되어, 3월에는 31일이 있는데도 28일에 청구한다. 한 번 당겨진 날이 돌아오지 않고 손실이 누적된다.

```
1/31 → 2/28 → 3/28 → 4/28 → 5/28      (31이 사라진다)
```

매월 말일 구독이면 넉 달 뒤엔 사흘 일찍 청구된다. 고객이 동의한 날짜가 아니다.

## 대안

**① 그대로 둔다.** 28일 이하 구독은 영향이 없다. 기각. 말일 구독이 드물지 않고, 틀린 날짜에
고객 돈을 긁는 것은 되돌리기 비싸다.

**② 항상 말일에 청구한다.** 계산이 단순하다. 기각. 15일에 시작한 구독까지 말일로 옮기는 것은
고객이 동의한 것과 다르다.

**③ 앵커를 따로 저장하고 매달 클램프한다.** 채택. `anchor_day`를 들고 매번 `(기준월, 앵커)`로
계산해, 그 달에 그 날이 없을 때만 말일로 당긴다. 당김이 누적되지 않는다.

```
1/31 → 2/28 → 3/31 → 4/30 → 5/31      (31이 살아 있다)
```

[Stripe 의 billing cycle anchor](https://docs.stripe.com/billing/subscriptions/billing-cycle)와 같은
방식이다. 앵커가 1월 31일이면 2월은 28일(윤년 29일), 3월은 다시 31일로 돌아온다.

## 결과

- `subscriptions.anchor_day` 추가. 구독 시작일의 일자가 앵커다
- 계산은 `BillingCycle.next(from, anchorDay, months)` 순수 함수로 분리
- 기존 행은 백필한다. 이미 두 번 이상 당겨진 행은 원래 앵커를 복원할 수 없다.
  한 번만 당겨진 행은 직전 주기 시작일에 원래 일자가 남아 있어 `GREATEST`로 살린다

## 남는 것

- **"매월 말일"을 원하는 구독은 여전히 표현할 수 없다.** 2월 28일에 시작하면 앵커가 28이라
  3월에도 28일에 청구된다. 진짜 말일 구독은 앵커에 별도 표식(예: `anchor_day = 0` = 말일)이
  필요한데, 그 요구가 실제로 있는지 확인한 뒤에 넣는다
- 청구 주기가 월 단위 하나뿐이다(`BILLING_PERIOD_MONTHS = 1`). 연 단위를 붙이면 2월 29일에
  시작한 연 구독을 어느 날짜로 갱신할지 같은 질문이 새로 생긴다
