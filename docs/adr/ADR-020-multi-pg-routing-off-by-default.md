# ADR-020. 멀티 PG 라우팅을 만들어 두고 기본으로 끈다

- 상태: 채택
- 날짜: 2026-09-05

## 맥락

`RoutingPgClient` 와 `PgSelector` 가 있다. 가중치로 주 PG 를 정하고, 서킷이 열린 경로는
건너뛰고, 요청이 <b>PG 에 닿지도 못했을 때만</b> 다음 경로로 넘긴다.

그런데 `app.pg.routing.enabled` 기본값이 `false` 다. **왜 껐는지가 어디에도 없었다.**

## 결정

**기본 off 를 유지한다.** 그리고 그 이유와 켜는 조건을 여기 적는다.

## 왜 껐나

**실계약된 PG 가 하나뿐이다.** 지금 라우팅 설정은 두 경로가 모두 `FakePgClient` 다.
가짜 둘 사이를 오가는 것은 <b>failover 를 증명하지 않는다</b>.

라우팅을 켜면 얻는 것으로 흔히 말하는 것이 셋인데, 셋 다 지금은 성립하지 않는다.

| 흔히 말하는 값 | 지금 성립하나 |
|---|---|
| 한 PG 장애 시 다른 PG 로 넘김 | ❌ 넘어갈 실 PG 가 없다 |
| 수수료가 싼 쪽으로 라우팅 | ❌ 계약 수수료가 하나뿐이다 |
| BIN·금액별 승인율 최적화 | ❌ 승인율 데이터가 없다 |

## 그럼 왜 만들어 뒀나

**로직의 값은 PG 가 실물이 아니어도 잴 수 있고, 실제로 쟀다.** `RoutingPgClientTest` 가
고정하는 것이 라우팅의 <b>어려운 부분</b>이다.

- 주 PG 가 성공하면 보조를 **부르지 않는다**
- 요청이 PG 에 **닿지도 못했을 때만** failover 한다
- **카드 거절은 failover 하지 않는다** — 다른 PG 도 거절한다
- **타임아웃도 failover 하지 않는다** — 미확정을 재시도로 읽으면 이중 결제다
- 어댑터가 미확정을 예외로 던져도 failover 하지 않는다
- 주 PG 서킷이 열리면 건너뛴다

**failover 에서 어려운 것은 "넘기는 것"이 아니라 "언제 안 넘기는가"** 이고, 그건 실 PG 없이도
고정할 수 있다. 그래서 로직은 만들고 스위치는 껐다.

## 켜는 조건

1. **실계약된 PG 가 둘 이상**일 것
2. 각 PG 의 **승인율·수수료를 실측**했을 것 — 가중치를 근거 없이 정하면 그건 그냥 순서다
3. **failover 가 이중 결제를 만들지 않는 것**을 실 PG 로 확인했을 것.
   지금은 "요청 미도달일 때만 넘긴다"는 규칙으로 막고 있는데, PG 마다 미도달 판정이 다르다

## 대가

**코드가 있는데 안 쓴다.** 쓰지 않는 코드는 썩는다. 그래서 테스트로 고정해 두고,
켤 조건을 여기 적어 <b>언제 다시 볼지</b>를 남긴다.

## 안 한 것

**두 번째 PG 를 붙이지 않았다.** 카카오페이는 테스트 가맹점코드(`TC0ONETIME`)를 공개하지만
API 키는 계정 발급이 필요하고, 그건 계약 절차다. **키 없이 어댑터만 만들면 검증할 수 없는
코드가 하나 늘 뿐**이라, 토스 어댑터를 만들 때처럼 <b>실제로 태워 본 뒤에</b> 넣기로 한다.
