# 운영자용 타임라인 서술 — 사례조사와 설계 (2026-09-05)

> 작업 중 문서. 만들면서 채운다.

## 0. 왜 이걸 만드나

`docs/11` 이 처음부터 자리를 지목해 뒀는데 비어 있었다.

> **그럼 어디가 AI 자리인가**: 어드민 화면이 20개인데 "주문 X번에 무슨 일이 있었나"를
> 한 번에 보는 곳이 없다. **흩어진 사실을 시간순으로 엮는 서술** — 판단이 아니라 서술이다

> **분류는 규칙이 낫고, 서술은 AI가 낫다. 둘을 섞으면 안 된다.**

그런데 지금까지 붙인 모델 둘은 이랬다.

| | 무엇 | 결과 |
|---|---|---|
| 상담 초안(13 문서) | 서술 — 다만 **고객용** | 검증 통과율 58 → 100% |
| 잔여 원인(14·15 문서) | **분류** | **껐다** — 규칙 대비 얻는 것이 0 |

**분류 쪽을 껐으면 서술 쪽을 켜야 그 판단이 완성된다.** 운영자용 서술이 비어 있었다.

---

## 1. 사례조사 — 업계는 이 자리에 무엇을 하나

### 토스페이먼츠 — 로그 분석·해결책 자동 제시 (기술지원)

n8n(워크플로 자동화)과 LLM 엔진을 연결해 **로그를 읽고 문제 해결책을 자동으로 제시**한다.
목표는 **10분 이내 응답**. 판단이 아니라 <b>흩어진 로그를 읽고 뭐가 문제인지 말해주는</b> 자리다.
지금 만들려는 것과 성격이 같다.

### 카카오페이 — 결제 MCP · Agent Toolkit (2025.08)

AI 에이전트가 결제 API를 호출하게 하는 **개발자용** 툴킷. Tool 8개
(`demo_payment`·`ready_payment`·`approve_payment`·`get_payment`·`cancel_payment` +
정기결제 3종). 안전장치는 **화이트리스트 기반 도구 필터링과 액션 단위 권한**
(`payment: { get: true }`)이다.

**이건 이번에 안 한다.** 고객 결제 API를 에이전트에게 여는 것은 ADR-008(AI 에 쓰기 권한을
주지 않는다)과 정면으로 부딪힌다. 카카오페이가 화이트리스트와 액션 권한을 먼저 깐 이유도
같은 문제를 풀기 위해서다. 원칙을 흔들면서 붙일 자리가 아니다.

### 해외 — 분쟁/차지백 증거 조립

결제·주문·CS 시스템에서 증거를 모아 **대응 자료(representment) 패키지를 조립**하고
카드망 기한을 추적한다. 승소율 30~40% 개선을 주장한다.

**이것도 이번에 안 한다.** 더 크고, 분쟁 실데이터가 없어 검증이 안 된다.

### 그래서 고른 것

**운영자용 타임라인 서술 하나.** 재료가 이미 다 있고(11개 도메인 조회 API, 사실 계약,
숫자 출처 검증), 읽기 전용이라 ADR-008 을 안 건드린다.

## 2. 설계

```
OrderTimeline(11개 도메인)  ← 상황 13 에서 만든 조회
        ↓
    FactPack                ← 상황 15 에서 만든 계약. 숫자·날짜를 값으로 함께 낸다
        ↓
 TimelineNarrativePort      ← 템플릿이든 모델이든 여기서 갈린다
        ↓
 NumericProvenanceGuard     ← 서술의 모든 숫자가 FactPack 에 있는지 대조
        ↓
   운영자 화면 (읽기 전용)
```

### 고객용 초안과 무엇이 다른가

받는 사람이 운영자다. 그래서 **가드가 줄어든다.**

| | 고객용 초안 | 운영자용 서술 |
|---|---|---|
| 내부 용어 | **막아야 한다**(누출 0/12 를 쟀다) | **그대로 나와야 한다** — 화면과 대조해야 하니까 |
| 말투 | 다듬어야 한다 | 상관없다 |
| 없는 숫자 | 버린다 | **버린다** (유일하게 남는 위험) |
| 나가는 곳 | 고객 | 사내 화면 |

### 기본은 모델 없음

`TemplateNarrativeAdapter` 가 기본이다. 두 가지를 한다.

1. 모델이 없어도 화면이 비지 않는다
2. **모델이 넘어야 할 자(尺)가 된다** — 모델 서술이 이것보다 나은지 재지 않으면
   "붙였다"만 남는다. 잔여 후보에서 그걸로 한 번 데었다

일부러 잘 쓰지 않는다. 시간순으로 잇기만 한다. **이 문장이 이미 충분히 읽을 만하면
모델이 필요 없다는 뜻이고, 그것도 답이다.**

## 3. 만든 것

| | |
|---|---|
| `TimelineNarrativePort` | 포트. 템플릿이든 모델이든 뒤에 숨는다 |
| `TemplateNarrativeAdapter` | **기본**. 모델 없이 사실을 시간순으로 잇는다 |
| `OllamaNarrativeAdapter` | 로컬 모델. `NONE` 을 기권으로 받는다 |
| `TimelineNarrativeService` | 숫자 출처 검증(가드 1개) |
| `GET /api/v1/admin/orders/{orderNo}/narrative` | 읽기 전용 창구. 못 만들면 **204** |

**가드가 하나뿐인 이유**: 사내 화면에만 뜨고 상태를 바꾸지 않는다. 고객에게 안 나가므로
내부 용어 누출도 말투도 문제가 아니다. 남는 위험은 <b>없는 숫자를 만드는 것</b> 하나뿐이라
가드도 그 하나만 뒀다. 필요 없는 곳에 가드를 늘리면 무엇이 왜 있는지 흐려진다.

**버린다, 고치지 않는다.** 출처 없는 숫자가 하나라도 있으면 문단을 통째로 버린다.
틀린 숫자가 섞인 서술은 <b>없는 것보다 나쁘다</b> — 운영자가 그걸 근거로 확정하면 틀린 판단이
장부에 남는다. 상황 13 에서 조회 실패를 조용히 넘기지 않기로 한 것과 같은 이유다.

**못 만들면 204 다.** 빈 문자열이나 "생성 실패" 같은 문장을 돌려주면 화면이 그걸 서술로 띄운다.

## 4. 잰 것 — 템플릿 대비

잔여 후보를 끄면서 배운 기준을 <b>만들면서 바로</b> 적용했다. 절대 품질이 아니라
<b>기존 방식 대비</b>로 잰다. 여기서 기존은 모델 없는 템플릿이다.

같은 사실 10건을 둘에 태웠다. 재현: `./gradlew evalTest --tests '*NarrativeLiftEvalTest*'`

| | 출처 없는 숫자 | 기권 | 평균 길이 |
|---|---|---|---|
| 템플릿(기존) | 0건 | 0건 | 324자 |
| qwen3:8b | 0건 | 0건 | **232자** (-28%) |

숫자로는 **28% 짧아졌다**. 그런데 길이만으로는 판단이 안 되므로 문장을 봤다.

**템플릿**
```
주문 ORD-N000 — 2026-08-01 · ORDER · 주문 생성 10,000원 그다음 2026-08-01 · PAYMENT ·
결제 READY → IN_PROGRESS (USER, TOSS_PAYMENTS) 그다음 … 2026-08-02 · RECONCILIATION ·
대사 AMOUNT_MISMATCH (거래일 2026-08-02) — 내부 10,000 / 외부 9,700.
```

**qwen3:8b**
```
주문번호 ORD-N000은 2026-08-01에 주문 생성 후 결제 상태가 READY에서 IN_PROGRESS로
변경되었고, 이후 DONE 상태로 변경되었습니다. 결제 완료 후 원장에 10,000원이 기록되었습니다.
2026-08-02에 대사 상태가 AMOUNT_MISMATCH로 변경되었으며, 내부 거래금액은 10,000원,
외부 거래금액은 9,700원으로 불일치했습니다.
```

**차이가 분명하다.** 템플릿은 목록에 접속사만 붙인 것이라 <b>원래 목록보다 읽기 어렵다</b>.
모델 쪽은 상태 전이를 문장으로 잇고 날짜를 한 번만 말한다. 상태 이름(`READY`,
`AMOUNT_MISMATCH`)은 그대로 남아 화면과 대조된다 — 운영자용으로 의도한 그대로다.

**이게 잔여 후보와 정확히 반대인 지점이다.** 거기서는 규칙이 이미 같은 답을 내고 있어서
모델이 동의하는 것 말고 할 게 없었다. 여기서는 규칙이 <b>문장을 못 쓴다</b>.

## 5. 남는 것

- **"읽기 좋은가"는 아직 못 잰다.** 지금 재는 셋(출처 없는 숫자·기권·길이)으로는 안 잡힌다.
  짧다고 좋은 문장이 아니다. 그건 사람이 읽어야 하고, 그 자리는 남는다.
- **표본이 합성이다.** 실제 타임라인이 내는 문장 형식은 그대로 썼지만 값은 만든 것이다.
  실데이터로 다시 재야 한다.
- **기본은 여전히 template 이다.** 모델 쪽이 나아 보이지만, 사람이 읽고 판단한 표본 없이
  기본값을 바꾸지 않는다. 잔여 후보에서 그 순서를 어겼다가 되돌렸다.
- **한 모델만 봤다.** qwen3:8b 하나다. 모델을 키우면 나아지는지는 안 쟀다.
